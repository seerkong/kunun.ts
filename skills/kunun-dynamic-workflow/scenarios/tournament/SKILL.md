# 场景：锦标赛择优（tournament）

## 何时用
任务的**解空间很宽、最佳路子未知**，单次生成不可靠，head-to-head 对比比"一把过"更可信：架构选型、文案 / 方案择优、开放式设计题。

## 流程骨架
1. **#Compete（扇出）** —— `ai_parallel` 让每个竞争者用**不同策略**（极简 / 为规模 / 为正确性与边界 / 为最快上线……）解**同一个**任务，各自产出方案。
2. **#Judge（择优）** —— 让裁判挑出最佳：
   - kon 友好做法：一个 judge agent 拿到**全部**方案，对照同一任务逐一比较，选出冠军并说明理由（output_schema 含 winnerIndex + reason）。
   - 若要更接近单淘汰赛（两两对决、逐轮晋级）：kon 缺通用 while，难表达动态轮数与配对；可用 `ai_pipeline` 固定几个 stage 近似几轮，或直接用上面的"一裁判选全部"。

`:output = [各方案 冠军]`。

## 关键陷阱
- 竞争者要用**不同策略**，不是 N 份雷同尝试，否则没有可比性。
- 完整单淘汰 bracket（动态轮数 + 配对）超出 kon 的控制流；kon 里用"一裁判选全部"或固定轮 `ai_pipeline` 近似即可。
- 裁判要"对照同一任务"比较，并给明确的取胜标准。
